## 실시간 분할 경로 비교 (`검증_20261004/segmenter_context_check.py`)
문장 WAV 6개를 썼습니다(해시는 `source_hashes.json`과 일치). 각 경로는 다음과 같습니다.
- (a) 8초 WAV 전체를 경계 모듈에 넣은 경로입니다. 이미 검증된 경로입니다.
- (b) 1024샘플 블록으로 흘려 기존 분할기를 거친 경로입니다.
- (c) 0.3초 주변을 남기는 분할기를 거친 경로입니다.

| 파일 | 길이 (a) / (b) / (c) 초 | 피크 수 | Shimmer % (a) / (b) / (c) |
|---|---|---|---|
| trial01 | 3.860 / 3.720 / 3.850 | 14 / 14 / 14 | 11.495 / 11.319 / 11.367 |
| trial02 | 4.170 / 4.105 / 4.165 | 17 / 17 / 17 | 13.055 / 13.033 / 13.033 |
| trial03 | 3.905 / 3.745 / 3.900 | 13 / 13 / 13 | 13.289 / 12.242 / 13.003 |
| trial04 | 3.715 / 3.580 / 3.710 | 16 / 16 / 16 | 11.832 / 11.875 / 11.865 |
| trial05 | 3.810 / 3.750 / 3.810 | 14 / 14 / 14 | 13.538 / 13.352 / 13.590 |
| trial06 | 3.915 / 3.795 / 3.905 | 16 / 16 / 16 | 13.426 / 13.767 / 13.727 |

- (a)는 인수인계 기록과 일치합니다. 길이 3.860/4.170/3.905/3.715/3.810/3.915초, 피크 14/17/13/16/14/16개입니다.
- (c)는 분석 길이를 (a)와 0–10 ms 차이까지 되돌렸습니다. 피크 수는 세 경로 모두 같습니다.
- Jitter·Shimmer는 (c)에서도 (a)와 똑같아지지 않았고, 모든 파일에서 (a)에 더 가까워진 것도 아닙니다. 경계가 5–10 ms만 달라져도 수십 분의 1 %p씩 움직이는 민감도가 다시 확인된 것입니다. 이 수정을 Jitter·Shimmer 정확도 개선이라고 주장하지 않습니다.
- 6개 모두 Jitter > 1.94%, Shimmer > 9.65%입니다. 따라서 이번 수정으로 판정 방향은 바뀌지 않았습니다.
- 0.3초는 결과를 보기 전에 정한 값입니다(스크립트에 미리 고정). 다른 값으로 맞춰 보지 않았습니다.
