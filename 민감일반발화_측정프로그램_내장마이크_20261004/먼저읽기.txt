일반·민감 발화 측정 프로그램 — Windows 64비트 · 노트북 내장 마이크용 (2026-10-04)

1. ZIP 압축을 모두 풉니다. Python 설치는 필요 없습니다.
2. START.cmd를 실행합니다.
3. '입력 장치' 목록에서 노트북 내장 마이크 항목(예: 마이크 배열 / Microphone Array)을 직접 선택합니다.
   - 프로그램은 기본 입력을 내장 마이크로 가정하지 않으며, 아무것도 고르지 않으면 시작하지 않습니다.
   - 각 항목 뒤 [MME], [Windows WASAPI] 등은 Windows 드라이버 방식입니다. 같은 마이크가 여러 번 보이면 [MME]를 권장합니다.
   - '· Windows 기본 입력' 표시는 현재 Windows 기본 장치라는 뜻일 뿐 내장 마이크라는 확인이 아닙니다.
   - 16000 Hz로 열 수 없는 항목은 시작 전에 안내창이 뜹니다. 그때는 같은 마이크의 [MME] 항목을 고르세요.
   - 사운드 매퍼·스테레오 믹스는 고르지 마세요.
4. 녹음 시작을 누르고 처음 1.5초는 조용히 기다립니다.
5. 일반 또는 민감 형식 문장을 말한 뒤 잠시 쉽니다.
6. 결과가 나오면 실제 정답 '일반 / 민감 / 모름'을 누릅니다. 정답을 누르면 다음 발화를 받습니다.
   - '측정 보류'된 발화도 정답을 누릅니다. 그래야 일반·민감별 보류율을 계산할 수 있습니다.
   - 정답은 프로그램 출력이 맞았는지가 아니라 방금 말한 문장의 실제 유형입니다.
   - 실제 개인정보 대신 실험용 가상 자료를 사용하세요.
7. 중지를 누른 뒤 '저장 폴더 열기'를 누릅니다. program/records의 새 speech_compare_날짜_시간.csv를 보내주세요.

계획된 20문장 대본을 순서대로 읽으려면 CONTROLLED_20.cmd를 사용합니다(실시간 전체 흐름은 아직 실제 PC에서 검증되지 않았습니다).
START와 CONTROLLED_20을 동시에 녹음시키지 마세요.

CSV에 기록되는 것
- 음향 피크율(자동 음절 수가 아님), Jitter, Shimmer, F0, 침묵 길이
- 개인 기준선 판정, 기존 비교 모델 판정, 사용자가 입력한 정답
- 측정 보류 발화: 보류 사유와 계산된 특징값(판정·기준선에는 사용하지 않음)
- 입력 장치 번호·이름·드라이버 방식, 실제로 열린 표본화율
- 분석 구간 시작·끝, 잡음·신호 대략 수준(dBFS), 주변 구간 검사에서의 Jitter·Shimmer 최소·최대

해석상 주의
- 기존 45개 기준선과 비교 모델은 구간 보정 전 방식으로 만든 과거 참고값입니다.
  지금 추출 방식·내장 마이크와 동일 조건이 아니므로 현재 판정을 정확도 검증 완료로 해석하지 마세요.
  원래 참고값 사본은 program/reference_baseline_original.json에 보존돼 있습니다.
- '현재 성적 보기'는 같은 화자의 반복 발화입니다. 독립 참가자 수나 일반화 정확도가 아닙니다.
- 실험용 보조 Shimmer, v2 피크 계수기, 임계값 변경, 재학습은 적용하지 않았습니다.

이 프로그램은 수치와 정답만 로컬 CSV로 기록합니다. 원본 음성은 저장하지 않으며 외부 전송·STT를 사용하지 않습니다.
